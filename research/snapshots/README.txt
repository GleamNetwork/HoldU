# B2「情绪急救与数字陪伴」政策与指南资料包

更新日期：2026-09-06

## 1. B2 原始命题边界

核心问题：在情绪崩溃的黄金干预窗口，技术如何编织一张去中心化的心理急救网？

命题提出五个思考入口：

1. 无感监测与语义预警：从文本、语音或行为变化识别消极状态。
2. 即时匹配与派单：依据紧急程度与志愿者画像，建立匿名 1v1 连接。
3. 危机熔断与专业转介：无法安抚且存在明确自伤倾向时，转接专业热线或启动紧急联系人流程。
4. 志愿者保护：接单上限、冷却期、督导和替代性创伤防护。
5. 临床可行性与长期管理：从一次陪伴延伸到持续随访和健康管理闭环。

比赛明确要求：演示不得使用真实危机用户数据；不得宣称替代专业心理或医疗服务；AI 只能为志愿者提供倾听提示与风险词提醒，不能代替受训人员作出危机判断。

## 2. 优先阅读顺序

### 第一优先：直接决定危机工作流

- `01_中国政策与规范/01_心理援助热线技术指南_试行_2021_官方要点.md`：中国心理援助热线的人员资质、知情同意、保密、风险来电流程、记录/交接/随访。
- `01_中国政策与规范/02_12356全国统一心理援助热线通知_2024_官方要点.md`：全国统一转介号码以及与 110、119、120 的联动要求。
- `01_中国政策与规范/03A_国家卫健委公报2026第3期_含危机干预方案.pdf`：到 2030 年的社会心理服务与危机干预网络、12356 省级平台和跨部门协作。
- `02_WHO与国际指南/01_WHO_心理健康危机服务_2021_EN.pdf`：以人为本、权利导向、避免强制/胁迫的危机服务设计。
- `02_WHO与国际指南/02_WHO_同伴支持心理健康服务_2021_EN.pdf`：同伴支持服务的组织、培训、边界、督导和权利保障。
- `02_WHO与国际指南/03_WHO_LIVE_LIFE自杀预防实施指南_2021_EN.pdf`：国家和社区层面的自杀预防与服务链路。
- NICE NG225（在线版，见国际索引）：明确反对用风险量表预测未来自杀/自伤，也反对仅按“低中高风险”决定治疗或出院；应聚焦个体需要和即时、长期安全。

### 第二优先：决定数据、AI 和责任边界

- `01_中国政策与规范/05_中华人民共和国个人信息保护法.pdf`：健康、生理、行踪等属于敏感个人信息；最小必要、特定目的、充分必要性、单独同意和影响评估。
- `01_中国政策与规范/07_互联网诊疗监管细则_试行_2022.pdf`：产品若跨入诊断、治疗或互联网诊疗，应进入医疗机构和医务人员监管框架；AI 不得冒充医生独立接诊。
- `03_AI与数字健康治理/01_生成式人工智能服务管理暂行办法_2023.pdf`：生成内容安全、个人信息保护、投诉处置和服务责任。
- `03_AI与数字健康治理/02_WHO_AI健康伦理与治理_2021_EN.pdf`：自主、福祉与安全、透明可解释、责任、包容公平、可持续六项原则。
- `03_AI与数字健康治理/03_WHO_健康领域大模型伦理治理_2024_EN.pdf`：医疗大模型的虚假权威感、自动化偏见、责任追踪、部署后监测和人类监督。
- `03_AI与数字健康治理/04_UNESCO_AI伦理建议书_2021_EN.pdf`：人权、尊严、公平、隐私、透明、问责和伦理影响评估。

### 第三优先：评估和证据

- `01_中国政策与规范/06_GBT45253-2025_互联网心理服务心理测评规范_标准信息页.html`：互联网心理测评的国家标准元数据。正式使用量表前需另行取得标准全文并核对授权、适用范围和解释资格。
- `02_WHO与国际指南/06_WHO_自伤自杀数字干预证据概况_2023_EN.pdf`：数字干预的证据强度、适用条件和局限；不能把“可辅助”写成“可替代危机服务”。

## 3. 对产品方案的直接结论

### 可以做

- 端侧运行的“关注信号”检测，输出原因标签与不确定性，不输出医学诊断。
- 志愿者 Copilot：倾听建议、禁忌表达提醒、流程核对、资源检索和复盘。
- 人工确认后的分级派单与升级，明确 12356、120、110 等转介路径。
- 与求助者共同形成安全计划、偏好设置和紧急联系人授权。
- 志愿者培训、督导、接单上限、冷却期、轮换和事后支持。
- 全链路审计：模型版本、触发原因、人工确认、转介时间、结果与事件复盘。

### 不宜做或必须改写

- 不把 AI 输出命名为“自杀风险诊断”或让模型单独决定是否强制干预。
- 不用单一量表/关键词命中预测未来自杀，也不让“低风险”自动结束服务。
- 不默认持续采集聊天、语音、位置、联系人；敏感数据需最小化并取得适当同意。
- 不让未培训志愿者独立处理高危事件；必须有专业热线/医疗/应急升级通道。
- 不承诺“零漏报”“精准识别”“阻断自杀”等无法验证且高风险的效果。
- “强制干预”建议改为“紧急安全升级”：触发条件、授权例外、人工复核、最小披露和事后告知均需写入协议。

## 4. 推荐的最小安全架构

`端侧信号检测 → 用户自主求助/温和询问 → 人工接单 → AI Copilot 辅助 → 人工安全核对 → 12356/120/110 等升级 → 交接与随访 → 事件复盘`

关键控制点：

- 检测层只产生“需关注信号”，不产生诊断结论。
- 高危升级必须由受训人员确认；极端紧急情况下按预先公开的安全协议处理。
- RAG 仅检索版本受控的官方流程、地区资源和沟通脚本；每条建议显示来源和生效日期。
- 模型无权直接拨号、通知联系人或披露身份；外部动作需人工确认并记录依据。
- 匿名匹配与紧急处置之间要有清晰的身份揭示条件和最小披露原则。
