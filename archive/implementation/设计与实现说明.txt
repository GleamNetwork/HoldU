# 同频 B2 三端联动原型

2026-09-07。成人、上海场景，所有初始个案及传感器数据为合成演示数据。

## 本次范围

用户端：今日状态、运动步数/心率/睡眠趋势、温和提醒、脚本式问答、自愿短问卷、找人陪伴、支持计划与数据开关。

志愿者端：单个演示工单、接单/暂停、同步消息、AI辅助摘要、当前安全核查、督导接管、模拟转介及随访。普通志愿者不独立完成临床安全评估，R0由专业值班/督导接管。

手表端：活动、心率、睡眠、轻提醒、快捷回复、主动求助；模拟器提供日常、运动后、睡眠改变、当前不安全、设备离线五个场景。设备数据本身不生成R0。

整体采用同一浏览器内的共享状态。桌面支持三端联动视图及独立端；手机按端查看。不接入真实热线、不调用大模型、不上传健康数据、不冒充已完成临床验证。消息为固定演示脚本，不支持可靠的任意语义危机识别；始终提供明确的主动求助按钮。

## 数据与交互边界

- 使用 React reducer 驱动会话、接单、分诊、转介回执和随访；页面刷新重置，不持久化聊天。
- 安全核查位于量表前并在全过程可随时触发。当前自杀想法/无法保持当下安全直接进入立即人工响应，无需同时满足计划、意图、手段三个条件。
- 量表展示稿独立于自由聊天。每题显式选择频率；AI不推断或补齐未回答项目，不将问卷分数转换为自杀风险等级。
- 心率读数清楚区分当前测量与静息基线。运动场景只说明情境，不能自动排除身体急症。
- 设备离线/数据关闭显示缺失，不显示0，不触发危机，也不阻止求助。
- 模拟转介必须已有人工接管及必要交接信息；R0不能以普通陪伴结案。

## 实现步骤

1. `lib/demo.ts`：合成场景、共享状态与纯函数转换；测试传感器变化不自动紧急升级、当前不安全绕过问卷、接单前不可转介、离线不记0。
2. `app/page.tsx`、`app/globals.css`：完成三端可识别首屏，打开预览后补全问答、量表、人工接单、模拟转介与随访。
3. `lib/wearable.ts`：统一 WearableSample 类型、BLE标准心率数据解析与连接；只在用户点击时请求设备，支持不可用、取消、断连。Apple/华为/Health Connect仅提供真实接入说明，不显示已连接。
4. `docs/硬件接入与演示指南.md`：官方链接、已有插件/示例、开发约束、三分钟演示顺序及已实现/待完成清单。
5. 执行纯函数测试、TypeScript检查、生产构建、精确本地URL响应检查；保存与私有发布。未连接硬件时不得声称完成真机测试。

## UI方向

名称暂定“同频”。以海蓝/青蓝为主色，用户端宽松友好，志愿者端信息密度更高，手表端深色、大字和大触控区。红色只用于明确的即时帮助入口和当前安全事件。所有演示控制放在界面外层，不混入面向求助者的文案。

## 依据与前置资料

参照资料包 `05_量表与分诊设计/B2_成人量表选型与转诊分诊流程.md`。本原型细化了先安全后问卷、当前安全不确定不能自动归入R3等规则。真实分诊仍需专业人员及机构规范。
