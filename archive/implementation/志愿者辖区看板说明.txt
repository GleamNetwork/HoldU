# 志愿者辖区看板、轮值与支持分层

## 使用入口

顶部保留「用户端」「志愿者端」，另增独立「管理端」；手表模拟是辅助演示入口。志愿者端固定为林然的身份，包含我的用户、今日陪伴、我的排班、求助与交接。只列出本人服务及片区待分配用户，不展示同事已承接的个案。社区 A / B 是上海场景下的虚构示范片区，不是实际地图，不申请定位权限，也不显示用户住址。

管理端包含辖区总览、今日支援总览、人员与排班、升级与交接；可切换值班负责人或专业督导。全员轮值和接待规则放在管理端，志愿者端只显示个人轮值。普通负责人不能打开联动聊天或查看原始复核依据；专业督导确认接管后才可打开会话。切换工作台保留接单、容量与交接记录，返回志愿者端自动恢复普通志愿者身份。

列表包含其他合成用户和联动的「小屿 TP-0921」。其他用户可演示接单、结束本次服务、交接或分层复核；小屿仍使用原来的日记授权、设备共享、未成年保护和专业转介流程。普通交接或专业接管后，原志愿者不再显示该会话全文入口。

## 本人休息与恢复

志愿者可主动申请休息，立即停止新接单，但仍保留当前服务责任。无待完成或待交接服务时，首页只显示小频恢复卡，不展示用户队列和危机数量。重新接单需由本人确认状态与私密环境，且仍须满足签到、容量和暂停开关条件，管理者不能代替确认。初始演示已经签到、自检并有一场进行中的陪伴；这里没有自动计时复岗、真实负荷监测或心理健康评估。

## 两种状态，分别记录

支持分层与支援进度不能混为一谈。会话结束不代表已恢复稳定；等待陪伴的人也不必然处于紧急状态。

| 当前支持分层 | 界面含义                                         |
| ------------ | ------------------------------------------------ |
| 相对平稳     | 按本人及专业人员已约定的计划联系；不表示没有风险 |
| 需要关注     | 进一步了解本人当前的困扰与支持需要               |
| 重点支持     | 协调更持续的专业支持                             |
| 即时安全支持 | 本人当前安全求助优先，不能等待普通名额或量表     |
| 待核实       | 缺少复核、信息不足或复核失效，不自动推断平稳     |

每条复核记录显示依据、复核人及时间。普通志愿者申请复核，专业督导在确认已核对本人情况并填写依据后记录结果。这里不提供当前紧急状态的降级按钮。数据缺失、接单、结束服务及手表数值均不能自动升降级。

支援进度另记为：暂无请求、等待支援、陪伴中、待接班确认、专业已接手、本次已结束。

分层是本原型的支持协调设计，不是临床量表、疾病严重度分级或自伤/发作预测工具。设计边界参考 [NICE NG225 1.6](https://www.nice.org.uk/guidance/ng225/chapter/recommendations#risk-assessment-tools-and-scales)：不能把总体风险分层用于预测未来自伤或决定是否提供服务。真实场景需要符合当地规范的专业评估，而不是仅靠本界面标签。

## 人员分工与接待上限

- 志愿者：普通陪伴、暂停新接单、提交交接和专业求助。
- 值班负责人：协调人手、核对接班、调整接待参数；不能确认专业接管或改变支持分层。
- 专业督导：专业接管、人工分层复核；普通管理身份不能替代。

默认每人每日接待上限 6 人，同时陪伴上限 2 人，仅为可调整的演示参数，不是临床、法律或行业标准。今日承接计数按用户去重；结束服务释放同时名额，不返还当天计数，白夜换班也不重置。负责人不能把上限调到已承接人数或正在陪伴数量以下。演示输入范围为每日 1–20、同时 1–4，并要求同时上限不大于每日上限。

接班同事有独立的当日承接记录和当前负荷，也受同一组每人上限限制。普通班次交接只能由原志愿者发起，负责人不能代替提交。交接申请提交后原负责人不变；收到接班确认并再次核对对方名额后才释放原人的同时名额。接班人满额时保留原服务，由负责人继续协调，不能静默丢单。专业接管后旧的普通班次交接停止执行；联动个案完成转介后，尚未确认的内部申请也同步结束，避免重复交接或遗留待办。

满额、暂停或离岗只阻止普通新接单，不阻止专业求助。确认收到“调配人手”只是管理侧收件，不表示额外人员已到岗，也不会增加普通接单额度。

## 排班演示

白班覆盖 08:00–20:00，夜班覆盖 20:00–次日 08:00；示例按 4 小时轮值段分配不同人员，不是一人连续工作 12 小时。林然的白班或夜班选项在演示中互斥；同一个演示日内切换班次保留当日计数。有本人尚未交接的服务时不能结束本班。

这是合成排班表，不读取现实排班、当前真实在线状态或后台计时；刷新或重置场景会清空本地演示变更，不构成实际自然日配额系统。

## 隐私和验证边界

演示身份下拉框仅用于演示不同操作权限，不是真实身份认证。当前过滤和状态机运行于单机前端，不能当作生产级授权边界。没有真实患者数据、人员通知、实时值守或医院接收回执；不自动复制日记正文到区域名单或交接摘要。

独立 HTML 与在线 Demo 使用同一套逻辑；离线版不发起真实 BLE 配对。上线真实服务前，必须补充机构审批、服务端身份和辖区权限、并发原子分配、真实排班与跨日处理、接班确认、最小披露和专业流程。

自动测试覆盖辖区过滤、上限、重复接单、接班方负荷、同日换班、分层复核、紧急流程及用户端联动。尚未进行浏览器点击、辅助技术、真实设备或临床验证。
