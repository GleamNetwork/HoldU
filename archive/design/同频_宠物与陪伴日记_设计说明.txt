# 同频：宠物伙伴与陪伴日记

设计稿｜2026-09-07｜仅供评审，尚未接入或修改现有 Demo。

## 设计主张

让用户感受到“今天的经历被认真记住”，同时帮助支持人员在获得授权后了解情绪变化。宠物是人工智能陪伴界面，不冒充真人、治疗师，也不代替现实中的朋友或专业支持。

参考 FUZOZO 的可选性格、萌趣互动与共同记忆机制，设计原创动物角色，不复刻其IP外形；不把其产品宣传当作医疗效果证据。

三款具备同样的安全能力、服务权限和转介入口，只改变外观与日常语言风格。用户自主选择，不按病情、诊断、量表或推测的性格分配。

## 首次进入：选一位伙伴

标题：今天，想和谁一起待一会儿？

三张并排角色卡：形象 → 名字 → 一句性格说明 → 一句见面话。选中后出现柔和描边，展示可选昵称和“就选你啦”。手机上纵向排列，避免只能靠颜色分辨选中状态。

同时保留“暂时跳过”。以后可以更换伙伴；日记归用户，不会因换宠物丢失。不用完成配对、购买硬件或填写问卷才能求助。

不设置亲密度下降、断签惩罚、宠物饥饿或“你不来我会难过”。用户退出、少用几天或拒绝记录，不触发负面反馈。

## 用户首页：宠物是入口，不是装饰

上方是一位会轻轻呼吸、眨眼的伙伴和一句简短问候；提供减少动态效果的选择。主要操作为“聊一聊”“安静待会儿”“记下今天”。

运动/步数、心率、睡眠保留在“身体小线索”卡片，标注时间、来源、缺失情况。日常提醒可以关闭，关闭后手机和手表一致生效。宠物不会用心率或睡眠数据直接宣称“我知道你焦虑/抑郁了”。

即时求助入口始终可见，不藏在养成玩法里。遇到本人表示当前不安全时，停止装饰性追问和写日记流程，沿用安全核查、专业值班接管和人工转介。

## 陪伴日记：先草稿，再确认，再分享

流程：用户选择今天哪些信息可以用于日记 → 生成带来源的草稿 → 用户核对/修改 → 保存为个人日记 → 按篇决定是否分享观察摘要。

默认日记为私密；不自动发送给志愿者，不把自由聊天直接当成已同意记入日记。用户可以只手动写一句，或者今天不记录。删除和撤回分享的具体能力，应在真实后端实现后才显示为可用。

### 用户看到的日记

日期：9月7日（虚构示例）

标题：今天，我们给自己留了一点空隙

“你说下午有点累。后来出去走了十分钟，你觉得轻松了一点。那件烦心的事还没完全解决，不过你愿意把它说出来了。明天如果愿意，我们再聊聊。”

页脚小字：AI依据你允许使用的内容整理，可能理解不准确，请确认后保存。

三个来源标签：本人原话｜本人填写的情绪｜已允许使用的设备记录。展开后逐条显示原始内容与时间；没有依据的细节不补写。

“今天的感觉”由本人选择或修改，可多选“疲惫、平静、烦躁、低落、轻松、说不清”，也可留空。不得把这些日常词自动换算成临床诊断或自杀风险等级。

### 支持人员看到的观察摘要

只对用户明确选择分享的内容生成摘要；界面显示“用户确认的记录”“来源”“尚待询问”，与用户侧保持可追溯关系。

| 字段 | 虚构示例 | 记录规则 |
|---|---|---|
| 本人自述 | 下午有点累，走了十分钟后轻松一点 | 保留用户原话及时间，不替换成诊断词 |
| 本人确认的情绪 | 疲惫、稍有放松 | 由本人明确确认；未选就显示未记录 |
| 相关情境 | 下午；散步前后 | 只记录已提供的情境，不推测工作或家庭原因 |
| 身体与行为线索 | 用户允许使用时才展示步数、睡眠、心率 | 可穿戴记录与本人自述分列；设备估算不当作情绪事实 |
| 当前安全 | 本次未询问 / 本人自述 / 需立即专业接手 | 不根据日记语气、开心表情或低分自动标记安全 |
| 希望获得的支持 | 待询问 | 不把“说过一句话”当成已同意联系家人或机构 |
| 人工补充 | 仅授权的支持人员填写 | 标记填写者与时间，与AI整理内容分开 |

用户修改草稿后，必须重新确认依赖被改文字的情绪标签与观察摘要；旧摘要不可继续作为已确认记录。分享只针对当前选中的篇目和字段，不默认扩大到全部历史。

## 一句话区分两层价值

用户端：陪我把这一天温柔地记下来。

支持端：在用户知情、确认和授权的前提下，形成有来源、能更正的情绪与生活观察记录。

这是产品交互设计，不是临床量表、诊断规则或正式医疗记录系统。真实应用仍需专业人员确定危机处理、角色权限、记录保管和披露制度。
