## 1. 主形象与暖色视觉

以用户提供的“小频”设计图为主要形象：白色柔软身体、短圆耳、大眼睛、蓝紫色耳机、胸前爱心。原有水豚/垂耳兔/小熊猫设计保留为备选素材，不再与小频争夺主形象位置。

| 用途 | 建议颜色 | 设计要求 |
|---|---|---|
| 页面底色 | 暖象牙白 #FFFBF5 | 保持干净，给角色和正文留白 |
| 陪伴、日记卡片 | 淡粉 #FBE7EB | 温暖柔软，不承担危险等级编码 |
| 轻活动、今日小事 | 鹅黄 #FFF1BD | 传达邀请，不表示警报 |
| 主按钮 | 深玫瑰 #A94360 | 搭配浅色文字，正式实现需验证对比度 |
| 正文 | 暖深梅 #503A46 | 不用低对比的浅粉色写正文 |
| 少量角色配色 | 原图蓝紫色 | 主要留给耳机和细节，不主导整个页面 |

主形象用于首页问候、聊天头像、日记页签和手表轻提醒。选择页由“不同物种竞争”调整为“先认识小频，再选喜欢的配色/昵称”；可跳过。外观选择不影响求助能力或安全处理。

表情可沿用倾听、安慰、鼓励、呼吸、微笑、休息六类，但不随推测的病情显示恐惧或悲伤，也不用角色的健康、饥饿或亲密度迫使用户运动、打卡、聊天。

参考图文案作如下调整：

- “没关系，一切都会好起来的”改为“现在不好受也没关系，我们可以一起找支持”。
- 不承诺系统始终在线；休息模式仍保留清晰的真人支持和紧急帮助入口。
- 日记由用户确认后保存；宠物不会宣称自己已经知道用户真实的内心状态。

正文建议16px起，常用标签14px起，按钮足够大；除颜色外保留文字和图标状态。动态可减弱或关闭，不使用闪烁和过强光效。

## 2. 三个主要界面

### 成人首页

小频和一句简短问候 → “陪我聊聊” → 本人选择今天的感受 → 身体小线索 → 活动邀请 → 陪伴日记。运动/心率/睡眠从孤立数字卡转为带解释和下一步选择的卡片。即时帮助始终可见。

### 青少年首页

小频使用平等、简短、不说教的语气。“今天有什么想说的？”配合心情表达、写日记、找可信任的人。“谁能看到我的记录”放在显著位置；不出现默认让家长查看全部聊天的入口。

### 活动关怀页

先展示可核对的变化，再询问情境：“最近记录到的活动比平时少一些，现在方便动一动吗？”四类回答为“正在学习”“正在休息”“身体不舒服”“提不起劲”，另有跳过/稍后/关闭提醒。选择身体不适后不继续推送运动任务。

概念图里的数字为合成示例，不是年龄标准或个人健康目标；页面图只表达视觉与交互方向，实际流程以前述规则和下文分支为准。

## 3. 未成年版：独立的权限与安全分支

建议首个可验证版本优先覆盖12–17岁，同时把更低年龄作为单独产品范围设计，而非直接复用成人对话和量表。

| 年龄范围（产品建议） | 交互与权限设计 |
|---|---|
| 18岁及以上 | 成人体验，个人日记和健康数据分别授权 |
| 14–17岁 | 青少年语气、学习与睡眠情境、可信任成人支持、年龄适配内容及专业转介；不能由成人模式换个标签实现 |
| 12–13岁 | 除青少年设计外，增加监护同意与儿童能理解的说明；账号同意、设备数据使用、日记分享分开说明 |
| 更低年龄 | 另做监护参与与儿童专业人员支持方案；本轮不设计独立自动化临床评估，不把成人问卷套用到儿童 |

法律依据：医疗健康信息及不满十四周岁未成年人的个人信息属于敏感个人信息；相关处理须符合特定目的、充分必要、严格保护及相应同意要求，处理不满十四周岁未成年人信息还涉及监护同意。实际服务的适用依据和流程需法务审查。[个人信息保护法，第28–31条](https://www.npc.gov.cn/npc/c2/c30834/202108/t20210820_313088.html)

不得将非必要设备数据授权与基本服务捆绑；拒绝额外数据或撤回同意不应阻断基本帮助入口。[未成年人网络保护条例，第32条](https://www.moe.gov.cn/jyb_xxgk/moe_1777/moe_1778/202310/t20231025_1087333.html)

以下为产品安全设计，不是对监护权或披露义务的法律结论：

- 家长/监护侧默认是支持计划、双方明确同意的摘要和权限设置，不把原始日记做成全天候监控面板；具体访问规则依法由机构制定。
- 向青少年说明保密范围及安全例外，不承诺绝对保密。
- 若求助涉及家庭伤害，不能自动把披露发给可能造成伤害的监护人；由受训专业人员选择安全联系人和适当保护流程。
- 紧急帮助与基本指引不等待设备绑定、量表完成或日记生成。
- 危机个案进入具备未成年人保护能力的专业值班，不由普通志愿者独立评估或自动结案。
- 有安静时段与休息提醒；不设置断签惩罚、运动排行、消耗热量挑战、付费解除危机限制或“只有小频懂你”的排他表达。
- 正式评估需核对具体工具的年龄、语言、地区验证及使用要求，不能直接沿用成人PHQ-2展示样稿。NICE亦强调适用年龄、情境和经验证工具。[NICE NG223](https://www.nice.org.uk/guidance/ng223/chapter/Recommendations)

## 4. 让步数变成关怀，而不只是显示数字

产品定位为“活动变化 → 情境确认 → 适度行动或人工支持”，而不是“步数低 → 精神疾病发作”。

### 两条不同的功能线

日常健康线：在用户允许、设备记录可靠且情境适合时，温和邀请走一小段、坐着伸展或进行本人习惯的安全活动。支持延期、跳过、关闭，允许行动不便者采用适配方式。

情绪支持线：活动持续偏离本人平时模式时，结合自述的兴趣、精力、睡眠和生活功能变化，邀请沟通；需要时请求专业人员评估。活动线索不生成诊断，不自行调整药物或治疗。

NIMH列出的抑郁表现可能涉及乏力、兴趣降低、睡眠及日常功能变化，也提醒其他疾病和药物可产生相似症状。因此本设计将“活动减少”作为需要询问的线索，而不设置步数诊断阈值。[NIMH：Depression](https://www.nimh.nih.gov/health/publications/depression)

### 分支流程

| 观察或本人回答 | 产品下一步 | 不应采取的行为 |
|---|---|---|
| 设备未佩戴、断连、时间过旧或数据不足 | 显示未知，必要时提示检查佩戴/同步 | 不把没有数据写成零活动，不判定失联危机 |
| 睡觉、上课、工作、乘车或主动休息 | 暂缓提醒，尊重安静时段 | 不打断睡眠/上课，不将合理静止标成异常 |
| 当前方便、无不适、本人愿意 | 提供可选的小活动；完成与否均可正常继续使用 | 不设统一一万步，不施加打卡或宠物受伤惩罚 |
| 身体不舒服、疼痛、明显头晕等 | 停止活动建议，询问是否需要现实中的医疗帮助 | 不用运动“测试”是否患精神疾病 |
| 提不起劲，且持续出现兴趣/精力/作息或功能变化 | 先关心感受、核查当前安全；可选年龄适配评估或受训人员沟通 | 不把量表置于紧急响应之前，不自动宣布发病 |
| 活动异常增多且睡眠需求明显减少，伴明显兴奋/易怒等自述 | 作为需专业核查的另一类线索，不继续鼓励冲运动目标 | 不认为活动越多越健康，不自动诊断躁狂 |
| 本人或现场人员报告当前不安全、严重身体急症或叫不应 | 进入即时现实帮助及专业处理，暂停游戏、日记和活动任务 | 不从单纯“没回复提醒”推断昏迷，不等待步数变化后再处理 |

活动增多与睡眠需求减少也可伴随躁狂状态，但需结合多方面信息进行临床判断；这支持本设计的“双向变化”关注，而非活动越多越好的单向奖励。[NIMH专家说明](https://www.nimh.nih.gov/news/media/2023/facebook-live-bipolar-disorder-in-adults)

如果已在接受精神心理治疗，可由本人和治疗团队预先商定个体早期信号及支持计划；产品只辅助执行获确认的计划，不自行学习出未经验证的“发作规则”。

### 最小数据与实现边界

需要区分：本人平时模式、当前步数/活动时段、佩戴和同步状态、当地时间、休息时段、本人活动能力及授权范围。设备估算的睡眠和即时心率必须独立标注；不默认采集位置。

当前 Demo 的标准BLE心率接口只提供心率，不提供连续步数、佩戴状态或可靠的静止时长；新增功能须有实际支持这些字段的数据源或明确的合成场景，不能声称已经监测到“久不活动”。

提醒间隔、个体基线窗口和变化幅度属于待验证产品参数，不是临床阈值。原型中若设置示例数值，必须标注“演示参数”；真实服务先验证准确性、误报、漏报、年龄适配和人工响应能力。

WHO建议不同年龄采用相应身体活动安排：成人通常为每周150–300分钟中等强度活动；5–17岁儿童青少年为一周内平均每天至少60分钟中高强度活动。这是一般健康建议，不是本产品的统一打卡目标、久坐告警阈值或精神障碍评估标准。[WHO身体活动建议](https://www.who.int/europe/news-room/fact-sheets/item/physical-activity)

## 5. 日记如何记录活动关怀

虚构示例：

“下午，你说自己有点提不起劲。我们先没有安排运动，你选择休息一会儿。后来你愿意和支持人员聊聊。”

用户确认后，观察摘要才记录：本人自述、时间、已授权的活动数据、本人选择、人工支持状态。若未回答，则保持“未确认”；不能写成“患者拒绝运动”或“抑郁发作”。是否完成活动不作为日记质量、情绪好坏或配合程度评分。
