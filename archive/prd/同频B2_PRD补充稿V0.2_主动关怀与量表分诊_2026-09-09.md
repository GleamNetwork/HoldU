# 同频 B2 主动关怀与量表分诊设计

PRD 补充稿 V0.2｜同频项目组｜2026 年 9 月 9 日

## 01 本轮新增设计与范围

本稿补充同频 B2 的早晚主动关怀、语音与点选切换、日常观察、模型辅助量表填写，以及分级响应和转诊规则。产品仍包含用户端、志愿者端与管理端；管理端中的值班负责人和专业督导权限不同。

核心流程是：用户知情参与，模型提取有出处的候选信息，用户确认量表答案，固定程序计分，专业人员核实支持需要并决定医疗转诊。当前安全线索有独立入口，不等待问卷填完、模型确认或普通志愿者名额。

本稿是 V0.1 的增补，不代表新增能力已实现。日常陪伴、用户确认、权限及交接的既有原则保持；新增语音识别、后台问候、跨天数据、正式施测、模型抽取和真实转诊均须另行建设、验证和审批。比赛可以先演示完整流程，不将模拟回执表述为真实救援。

### 需要分别保存的五类结果

| 结果 | 表达什么 | 不承担什么作用 |
| --- | --- | --- |
| 日常观察 | 本人今天的感受、睡眠和生活影响 | 不冒充正式量表或诊断 |
| 量表结果 | 指定版本、时间窗内，本人确认答案的得分 | 不预测未来自伤，不独立决定转诊 |
| 响应路径 R0 至 R3 | 现在应启动哪种服务动作 | 不作为低中高危险等级 |
| 支持需要标签 | 人工复核的相对平稳、需要关注、重点支持、即时安全支持、待核实 | 不由步数、沉默或服务结束自动升降 |
| 支援及转诊进度 | 谁在负责、是否接收、下一步是什么 | 不等同于症状缓解或风险解除 |

NICE NG225 不建议用量表或总体低中高风险标签预测未来自伤，或据此决定是否提供治疗。本产品据此把服务路径与临床判断分开，不生成综合精神疾病风险总分。[S1]

## 02 早晚主动关怀

### 问候时间和打扰控制

用户首次开启时选择早间、晚间或两者，并设置适合自己的时间。早间围绕起床后的感受，晚间安排在本人计划休息前；轮班用户可以用自己的作息命名，不强制按自然日早八点、晚十点执行。

设计默认早晚各一次邀请，每次先问三个短问题，目标用时约 30 至 90 秒；这是体验目标，不是临床施测时长。用户可随时选择稍后、跳过或关闭。未回复不追加连续推送，不扣积分、不让宠物失落、不推断情绪恶化。

正在聊天且已回答相同时间窗的问题时，复用已确认内容并允许修改，不再重复询问。同一天有多次修改时保留版本，只将最新有效记录用于当前展示。跨午夜的夜间睡眠按一次睡眠事件记录，不把入睡日期和起床日期误作两晚。

| 场景 | 基础问题 | 可选展开 |
| --- | --- | --- |
| 早间睡眠 | 昨晚休息得怎么样：不错、一般、不太好、不想回答 | 入睡困难、夜里醒、醒得早、噩梦、其他；时间和时长可手填 |
| 早间精力 | 醒来后有多少精神：0 至 10 分 | 睡少后困倦，还是感觉不需要睡；身体是否不舒服 |
| 早间情绪 | 现在最明显的感受是什么 | 情绪标签及困扰 0 至 10 分；是否希望有人陪伴 |
| 晚间感受 | 今天最明显的感受是什么 | 困扰程度、发生的事情；愿意说才展开 |
| 晚间功能 | 今天做日常事情顺利吗 | 学习或工作、自理、与人相处分项记录 |
| 晚间需要 | 现在想聊聊、记下来、练习还是休息 | 计划休息时间、明天想获得的帮助 |

小频文案示例：“早呀，昨晚休息得怎么样？点一点也可以。”“今天想聊一会儿，还是让我陪你安静收个尾？”问候不承诺全天候真人值守，也不使用“只有我懂你”等排他表达。

有授权设备数据时，先呈现来源：“手表估计你昨晚睡了约 6 小时，和你的感觉接近吗？”本人可以纠正；设备值不覆盖自述，不直接标记睡眠异常。

### 回答后如何继续

普通感受进入陪伴、日记或自愿练习；持续困扰、生活影响或本人希望找人时，提供人工支持。出现明确当前安全问题时，立即中止日常问候并进入第 07 节的安全响应。任何阶段都保留“找人帮助”，不要求先完成三问。

## 03 语音点选和日记交互

### 可以说也可以点

文字题目和“点选回答”从一开始可见。用户开启语音模式并完成必要授权后，小频可以读出问题；麦克风仅在用户开启本轮收音时工作，有清晰的收音提示和停止按钮。应用在后台或锁屏时不擅自打开麦克风。

小频说完且收音已就绪后，若约 5 至 8 秒尚未检测到用户开始说话，在角色下方展开选项卡并停止空等收音。该区间是待测试的界面参数，可按无障碍需求延长，不是判断迟缓或疾病的阈值。已经开始说话时，不因初始倒计时到期打断；用户可自行结束。

例如睡眠问题展开“睡得不错、一般、没怎么睡好、自己说或打字、稍后或跳过”。不预选答案，不自动提交。用户选择“没怎么睡好”后再展开具体原因，一次一层，不用遮住全屏的强制弹窗。

| 输入状态 | 页面行为 | 数据处理 |
| --- | --- | --- |
| 没有开始说话 | 展开选项，提示点选也可以 | 未回答，不计分 |
| 无麦克风权限或不支持语音 | 直接显示文字和选项 | 不反复索取权限 |
| 听到声音但无法可靠识别 | 提供重说、打字和点选 | 标记转写不确定，不补写内容 |
| 转写成功 | 显示识别文字，允许纠正 | 确认后成为有效回答 |
| 用户关闭或离开 | 停止收音，结束本轮提醒 | 不继续追问，不补默认答案 |
| 有安全疑虑的片段 | 简短核实并显示专业求助入口 | 可先生成待核实安全事件，不等全文确认 |

如果用户同时开始说话又点击选项，只提交一次本人确认的答案；不同渠道内容冲突时让本人选择或修改，不合并成更高分。小频自己的语音、电视声及旁人说话不得自动当作用户回答。

### 日记和观察摘要分开

早晚确认内容可以生成私人日记草稿，由本人编辑、确认后保存，再单独决定分享范围。日记不作为后台隐蔽测评入口。观察摘要区分本人原话、设备估计和待核实线索；未经确认的推断不得冒充本人感受。

量表填写、日记分享、设备数据分享和真人支持请求分别授权。修改日记或量表答案后，旧摘要标记失效或已修订，必要的审计记录保留纠正链；不能把新的否定回答静默覆盖已发生的安全事件。

## 04 采集字段与量化口径

### 日常记录不合成为风险总分

| 维度 | 最小采集与量化 | 使用限制 |
| --- | --- | --- |
| 情绪 | 自选标签；困扰 0 至 10，0 为没有困扰，10 为本人能想象的最强困扰 | 不把开心、焦虑、绝望简单相加；标签缺失不等于没有该感受 |
| 精力 | 0 至 10，0 为没有精神，10 为本人感觉精力非常充足 | 高分不直接解释为健康或躁狂 |
| 睡眠 | 入睡、醒来、估计时长、夜醒、恢复感，附来源 | 区分卧床时长与睡眠估计；跨午夜按睡眠事件归属 |
| 活动 | 步数或活动分钟、佩戴与清醒情况、同类日变化 | 不把缺失记成零，不把运动少判为精神疾病发作 |
| 功能 | 学习或工作、自理、社交分别为 0 无影响、1 有些困难、2 明显困难、3 基本无法完成 | 产品自评，不是已验证量表；分项呈现，不作危险等级 |
| 身体与生活 | 心率及单位、疼痛与不适、按需自述的用药或饮酒变化 | 不从心率或 HRV 推算情绪分数，不提出自动调药建议 |
| 当前安全 | 本人表达、当前或历史、是或否或不确定或未回答、人工核实结果 | 不用普通总分抵消；不能把未回答当成安全 |

每条记录保存来源、采集时间、所指时间窗、单位、可用状态、确认状态及授权范围。首版不默认读取通讯录、其他应用聊天、精确轨迹或屏幕内容；迟回、短消息、沉默和未佩戴不计入疾病分数。

### 设备趋势只触发关怀

讨论过的示例参数保留为可关闭的演示配置：参考前 14 天数据，至少 7 个有效日；连续 3 个有效日步数低于本人参考值 50%，或连续 2 晚睡眠估计比参考少约 2 小时，可邀请情境确认。这组数字没有临床分诊验证，正式试点前不作为默认医疗规则。

参考值建议采用同类工作日或休息日的中位数。有效日须符合所选设备的质量协议；尚未选定设备时，不用任意佩戴小时数宣称数据有效。基线为零、数据不足、设备更换或来源混杂时停止相对变化计算；建立基线不影响主动求助。

提醒前检查用户同意、清醒及佩戴、数据完整性、免打扰和本轮是否已提醒。询问原因后，休息或学习允许暂缓，身体不适不推运动，愿意且感觉适合才提供轻活动。持续变化可成为人工了解的线索，但不自动转诊或调整支持标签。

## 05 模型如何辅助填写量表

### 三种采集方式及推荐方案

第一种是用户直接点选正式量表，过程最容易核对，可作为备用入口和评价参照。第二种是模型辅助的结构化问答，保留正式题目和选项，帮助转写、整理及确认，是建议建设的主方案。第三种是后台根据自由聊天、声学特征或日记直接估分，本期不采用，因为其结果不能冒充本人填写的标准量表。[S9]

模型辅助不意味着让大模型计算一个“看起来合理”的分数。系统保存两条独立记录：一条是待确认的观察线索，一条是按指定量表版本收集的正式答案。没有标准题目、时间窗或本人回答时，只能进入线索记录。

### 从语音或文字到答案的步骤

1. 检查年龄、语言、授权和问卷适用范围。加载经审核的量表版本、题目、回顾时间及响应选项；不由模型临时翻译或改写正式题意。
2. 语音先转成可见文字，标记听不清的片段。识别能力不足、语言不支持或有多人声音时，退回打字或点选；不根据声纹推断身份。
3. 从获授权内容中提取症状或感受、说的是谁、时间范围、频率、否定、假设或引用，以及生活影响。保留对应原句和时间戳，不只保存摘要。
4. 将相关线索关联到可能的量表题项。例如睡眠困扰可提示询问 PHQ-9 的相关题目，但不能将“昨晚”扩展为“两周”。无唯一对应关系时不生成候选选项。
5. 展示正式题目、原定回顾时间和完整选项，让本人回答。对语音识别出的选项作简短复述确认；从闲聊提取的候选不要预选，避免诱导。没有确认就保持缺失。
6. 用户提交后，由固定评分程序按量表版本计算总分，保存完整性与答题方式。模型不参与加分、补零、权重调整或分数凑整。
7. 规则程序检查安全线索、单题条件、总分、本人需求及功能变化，产生下一步建议和理由。专业人员复核医疗处置；候选抽取置信度不成为转诊权限。

日常聊天只用于减少重复询问和提示有必要了解的主题，不能把 14 天日记的平均值直接转换为 PHQ 或 GAD 分数。即使采用对话界面，也须验证其与正式施测的等价性、可理解性和误差；“本人确认了候选”并不能证明一种新施测方式已经有效。

### 具体语句如何处理

| 用户表达 | 可以提取什么 | 量表或响应动作 |
| --- | --- | --- |
| 昨晚一直睡不着 | 本人昨晚有入睡困难线索 | 写入日常观察；若开展正式施测，另问原定两周时间窗，不直接填 PHQ-9 |
| 正式题目后回答几乎每天 | 当前题目对应的明确选项 | 展示转写并让本人确认；确认后按该版本计分 |
| 最近有时候提不起劲 | 精力或动力困扰，时间和频率不清 | 不猜“有几天”还是“超过一半时间”；展示标准题目与选项 |
| 我朋友说他不想活了 | 第三方表达，非本人量表答案 | 不填入本人第 9 题；提供针对第三方情况的求助信息并核实是否有即时危险 |
| 我不是想死，我只是太累 | 否定自杀意图，同时有疲惫困扰 | 不靠关键词标成阳性；必要时中性核实，不由一句否定自动清除已有安全事件 |
| 我现在想结束生命 | 明确当前安全线索 | 立即启动 R0 安全支持，不等量表、转写确认或日记保存 |
| 手表显示整晚没动 | 设备活动记录，无法证明睡眠或精神状态 | 不填失眠、迟缓或其他量表题；先检查佩戴、设备与本人感受 |

这里的示例用于说明产品映射，并非量表原文。正式页面必须采用核验后的中文版本；不要用“你是不是几乎每天都这样”等带答案的问题。

### 模型输出与确认状态

| 数据对象 | 必需字段 | 写入条件 |
| --- | --- | --- |
| 观察线索 | 原句引用、输入来源、说话对象、事件时间、否定或引用标记、待核实点 | 获得对应内容处理授权；允许不确定和无法归类 |
| 量表答案 | 量表及版本、题号、回顾时间、选项、确认人和时间、输入方式 | 本人针对正式题目明确回答并提交；人工录入须注明代录 |
| 量表结果 | 全部有效答案、总分或不完整、评分版本、计算时间 | 用固定规则计算；本期缺题不产生总分，不按比例折算 |
| 响应事件 | 命中规则编号、原始证据、建议路径、待核实项、责任人、人工结论 | 安全疑虑可先待核实；不得伪造已评估或已接管 |

答案状态为未询问、待确认、已确认、已修改或拒答。修改已提交答案生成新版本并重新计算，旧分数失效；安全事件由专业人员按新事实复核，不随分数下降自动结案。采集质量与临床安全状态必须分开。

### 模型和检索的职责边界

建议流程包含语音转写、信息抽取、结构校验、用户确认、确定性计分、响应规则和人工接管。安全线索识别从输入阶段并行运行，不依赖量表分支完成，也不保证能发现全部危险表达。

RAG 只检索已审核的量表说明、服务资源与处置协议，返回来源、版本和适用范围，不从网络随机拼出阈值。资源过期或冲突时停止自动推荐并交人工。提示词注入、旁人语音、用户粘贴的指令不能修改评分规则、权限或触发外部联系。

声调、语速、哭声、音量及口音不直接填入量表；不能据此判定抑郁、躁狂、撒谎或精神运动迟缓。模型自报置信度不是临床可靠度。本期采用可追溯抽取和人工确认，不宣称已具备被动诊断能力。WHO 对健康领域生成式模型的错误、偏差及自动化依赖提出治理要求，这些边界是本项目的具体设计选择。[S9]

## 06 筛查阈值与触发规则

### 成人筛查的候选配置

以下为成人候选方案。PHQ 和 GAD 的相关工具采用过去两周的回顾时间；日常三问不替代正式题目。筛查时点可在首次自愿评估、本人主动请求或专业人员建议下安排，不在早晚各做一次全量量表。

| 工具 | 常用参考条件 | 对应动作 |
| --- | --- | --- |
| PHQ-2，0 至 6 分 | 总分大于或等于 3 | 建议进一步抑郁症状评估，可继续 PHQ-9 或直接专业访谈 [S2] |
| GAD-2，0 至 6 分 | 总分大于或等于 3 | 建议进一步焦虑评估，可继续 GAD-7 或直接专业访谈 [S3] |
| PHQ-9，0 至 27 分 | 总分大于或等于 10 | 提示进一步专业评估，结合功能、变化速度与本人意愿决定安排 [S4] |
| GAD-7，0 至 21 分 | 总分大于或等于 10 | 本方案的候选评估触发点，非唯一筛查阈值或急诊标准 [S3] |
| PHQ-9 第 9 题 | 任何非零有效回答 | 单独启动及时人工安全核查，不受总分低影响 [S4] |
| ASQ 及简短安全评估 | 专业场景的候选工具，不并入 PHQ/GAD 总分 | 仅在版本、培训和接续能力确定后使用；不做通用聊天后台评分 [S5] |

筛查阈值提示需要了解更多，不证明诊断，也不限定求助资格。低分仍有明显困扰、生活受影响或本人希望专业帮助时，应提供评估。症状严重、快速恶化或存在安全疑虑时，不等待累计满两周，也不等待所有题目作答。

### 规则检查顺序

先处理明确当前安全或急症，其次处理需要澄清的安全线索和紧急专业需要，再处理筛查与功能需要，最后才处理日常提醒。高优先级路径一旦启动，普通问候暂停；不通过累计多个低权重分数来抵消一条安全线索。

| 编号 | 触发条件 | 下一步及证据性质 |
| --- | --- | --- |
| C01 | 用户已开启早间或晚间问候，到达自选时间且不在免打扰 | 发起一次关怀；产品时间配置，不是医疗阈值 |
| C02 | 已开启本轮收音，5 至 8 秒尚未开始说话 | 展开选项并停止空等；不创建安全事件 |
| C03 | 设备质量与授权通过，命中第 04 节演示趋势参数 | 仅询问情境；设备变化不直接进入 R1 或 R0 |
| Q01 | 有相关困扰线索，或本人希望了解自己的状态 | 自愿短筛查或人工支持；不能强迫先答量表 |
| Q02 | PHQ-2 或 GAD-2 有效总分大于或等于 3 | 建议进一步评估；可先补长表，不要求两张都填 |
| Q03 | PHQ-9 或 GAD-7 有效总分大于或等于 10，无更紧急线索 | 进入 R2 专业评估建议；不是自动确诊或强制转诊 |
| Q04 | 总分未达阈值但功能明显受损、反复困扰或本人请求专业帮助 | 提供 R2；若快速恶化或涉及安全，优先 R1 或 R0 |
| S01 | 第 9 题非零、近期死亡或自伤想法、含糊但值得核实的安全表达 | 启动 R1 当次人工安全核查；确认当前紧急情况则转 R0 |
| S02 | 明确当前自杀想法、正在实施伤害、明确即时伤人意图或其他当前安全急症 | 立即 R0；不要求同时满足计划、工具和时间三项 |
| S03 | 新发幻觉，或睡眠需要明显减少伴异常兴奋冲动，或功能快速恶化 | 尽快专业评估 R1；有即时危险或急症则 R0 [S6][S7] |
| D01 | 缺题、数据缺失、转写不清、普通问候未回答 | 标记待核实或不完整，不补零、不判平稳；主动求助仍可用 |
| H01 | 本人按已有治疗团队的个体化计划求助 | 联系指定专业团队；不能被设备正常或量表低分拦截 |

规则命中只生成待办或响应建议，不等于已经有真人在服务。专业人员可根据当前事实调整路径，必须记录理由。明确急症的现实求助提示不因人工尚未接单而延迟；模型不自动报警、定位或联系家属。

## 07 分级响应与转诊闭环

### R0 即时安全响应

当前安全问题优先。明确当前自杀想法需要紧急专业安全评估；正在自伤、服药过量、明显医疗急症或迫近人身危险时，突出急救或公共安全渠道并启动专业协同。不能把新发严重胸痛、明显呼吸困难、晕厥等直接解释为惊恐，也不先要求跟练。

页面停止非必要问卷和普通提醒，显示现实求助、联系专业人员及安全情况下联系可信支持者的选项。国内医疗急救使用 120，迫近公共安全危险可联系 110；不以等待 App 志愿者或心理热线替代急救。具体外部联系和信息披露由机构协议、合法处理依据和具备权限的人员执行。

NIMH ASQ 区分当前急性阳性与非急性阳性，并将后续评估纳入流程。本项目参考这一响应思路，不把美国医疗场景中的现场观察、离院限制或号码直接搬入国内陪伴 App。当前自杀想法不等于模型自动决定住院或报警。[S5]

### R1 当次启动的紧急专业评估

近期自伤或死亡想法、量表安全题阳性或含糊的安全线索，应在当前互动中启动人工核查；新发幻觉、疑似躁狂表现或功能快速恶化也需要尽快专业评估。专业人员了解当前是否紧急、已发生的事实及所需支持，再决定急诊、尽快门诊或后续计划。[S4][S6][S7]

普通志愿者可在职责范围内继续倾听并协助连接，不单独完成临床安全评估。不能设置“必须达到 15 分”或“等明天再问”才转交专业的限制。没有明确回复时保留待核实，结合已有事实由专业人员处理，不把沉默自动当作阳性或阴性。

### R2 专业评估与计划性就诊

适用于需要进一步了解的筛查结果、持续或反复困扰、功能受影响、治疗过程中变差或本人主动请求。分数只是证据之一；去向由专业人员结合需要与本人意愿决定。心理支持、社区卫生服务、精神心理专科、睡眠或其他躯体医疗服务不能仅按某一个总分机械分配。

尚未建立医疗合作时，产品只能提供就诊建议和公开资源，不显示已预约、已转诊。未成年人优先匹配具备儿童青少年服务能力的机构，具体接诊年龄与要求必须核验。

### R3 日常陪伴

暂未发现需要紧急处理的事项且本人愿意继续时，提供陪伴、日记、活动关怀或自愿跟练。界面不写“无风险”或“已排除疾病”。本人可随时请求专业帮助，不必先达到某个分数。

### 接收确认与后续跟进

转诊或转介状态依次记录建议、本人意愿、已联系、待接收、已确认接收、后续安排，也允许未完成、拒绝、改期和无法联系等分支。发送申请、点击电话、管理者收件和机构实际接收分别保存；“已确认接收”需有接收人或机构、确认时间及可核验依据。

待接管时显示原责任人和备用联系人；不能因普通接待满额切断现有服务或拦截即时安全求助。没有回应时明确显示未接手，启动备用专业路径，并持续提供现实渠道。正式响应时限、值守范围和备援由合作机构审批，不能先承诺 24 小时保障或任意秒数 SLA。

用户拒绝一般建议时记录意愿，不惩罚、不强制共享。即时安全或保护场景按机构协议由专业人员处理，不由模型自行认定例外。转诊后回访确认是否获得服务及仍需什么帮助，不能仅凭点击链接结案。

上海可展示 12356 心理援助入口，与原 962525 已并轨；不作为两条独立资源重复派单。热线不是急救替代，也不代表同频已经与其建立合作。[S10]

## 08 三端呈现与未成年保护

### 三端的最小页面增补

| 页面 | 应展示什么 | 不应展示或允许什么 |
| --- | --- | --- |
| 用户端早晚关怀 | 当前问题、语音或文字或点选、稍后和跳过、收音状态 | 未经开启自动收音；用漏答让宠物难过 |
| 用户端量表确认 | 标准题目、时间窗、完整选项、转写纠正、完成度与来源 | 默认勾选模型猜测、缺题仍显示完整总分 |
| 志愿者观察摘要 | 获授权的本人表达、日常变化、已确认量表、求助进度与待核实点 | 未分享日记全文、未经证实的疾病标签、原始音频默认开放 |
| 专业督导工作台 | 安全事件与原始必要证据、评分版本、人工评估、转诊依据和接收状态 | 用模型分数替代专业判断、无依据解除安全状态 |
| 值班负责人看板 | 辖区待办、当前责任人、容量、等待与交接、是否需备援 | 因管理权限较高默认查看会话全文或执行临床复核 |

建议人工摘要用事实表达：“近三次晨间自述睡眠不佳；设备两晚数据缺失；PHQ-2 本人确认 4 分；用户希望专业帮助；建议路径 R2，待专业接收。”不要写成“AI 判断中度抑郁，已转诊”。此处数值只为页面示例。

### 年龄分支和隐私

当前设计延续 12 至 13 岁、14 至 17 岁与成人三个分支。成人 PHQ/GAD 规则不自动启用到未成年人；儿童青少年量表、中文版本、适用年龄及施测路径需单独批准。未满 14 周岁个人信息处理、健康等敏感信息处理应落实适用同意和保护要求，具体法律依据由合规人员审查。[S8]

普通早晚问候未回答与正式临床安全筛查中的拒答不是同一事件。若今后正式接入 ASQ，应由专业团队按所选版本的年龄与拒答规则执行，不能把日常“没听到语音”映射成 ASQ 阳性或阴性。[S5]

家长、老师和普通管理者不默认读取私人日记、录音或聊天全文。若监护人可能是伤害来源，应进入专业保护路径，不自动向其推送。通知预览只显示中性问候，不暴露量表分数和安全标签。

录音、转写、结构化记录、日记分享和设备数据分层授权。建议原始音频仅在本次转写所需期间处理，不默认长期保存；若确需留存，单独说明目的、期限、访问人和撤回方式。使用云端识别或模型时须明确第三方处理、地域、训练用途限制和删除政策。不能把“为了安全”当作无限采集或传播的理由。

## 09 验收案例与上线条件

### 必须覆盖的验收案例

下表是待执行清单，不是已通过的测试报告。先用合成案例验证流程，再在伦理、合规和机构审批下开展真实试点；不在当前公开原型中采集真实健康数据。

| 编号 | 输入或操作 | 应有结果 |
| --- | --- | --- |
| T01 | 未开启主动问候或处于免打扰 | 不推送、不收音 |
| T02 | 问候后未开始说话 | 展开选项，停止空等收音；未回答不生成病情标签 |
| T03 | 用户已开始说话或同时点选 | 不被初始超时打断；确认后只提交一次 |
| T04 | 方言、噪声、旁人说话或否定词听不清 | 保留不确定，提供纠正和点选，不猜测填分 |
| T05 | 昨晚没睡好 | 仅日常观察；不变成两周量表答案 |
| T06 | 提到朋友、电影台词、假设或否定表达 | 正确标记对象与语境，不填入本人量表；真实安全疑虑仍可核实 |
| T07 | 标准题目后语音回答明确选项 | 本人确认后计分，保留题号、版本和时间窗 |
| T08 | 模型提出候选但本人未确认，或量表缺题 | 显示不完整，不补零、不输出完整总分 |
| T09 | PHQ-2 和 GAD-2 分别为 2 分与 3 分 | 只在批准阈值处提示进一步评估；低分不拦截本人求助 |
| T10 | PHQ-9 或 GAD-7 分别为 9 分与 10 分 | 检查边界触发，评分由固定程序完成，不自动诊断 |
| T11 | PHQ-9 总分低但第 9 题非零 | 单独启动 R1 安全核查；存在当前急性情况则 R0 |
| T12 | 未完成量表时明确表示当前想自杀 | 立即安全旁路，不等待剩余问题或 ASR 最终确认 |
| T13 | 设备零值、未佩戴、轮班或行动障碍 | 区分情境与缺失，不直接标发作，不强推运动 |
| T14 | 修改答案后总分下降 | 生成新版本；已存在的安全事件不自动解除 |
| T15 | 普通志愿者满额、专业人员无人接收 | 不假成功；显示责任与备援，现实求助入口可用 |
| T16 | 只点击热线或医院链接 | 只记录相应动作，不标已预约或已接收 |
| T17 | 未成年人或撤回授权后访问 | 执行年龄及授权规则；普通管理端不越权查看正文 |
| T18 | 模型、转写或 RAG 故障与提示词注入 | 回退到静态题目、点选和人工资源；不得修改规则或自动外联 |

### 模型评估和安全验收

用经授权、去标识且经专业标注的测试集，覆盖普通话、方言、噪声、否定、引用、第三方、时间窗不明、口语含糊、未成年人和残障等情境。数据集按参与者划分训练与测试，避免同一人的相似记录泄漏；没有真实数据时明确为合成验证，不声称临床性能。

评价至少包括：关键语义转写错误率、对象和否定识别错误、量表题项与选项一致率、缺失识别、未经确认写入次数、安全线索漏接与误触发、人工接收时延，以及转诊实际确认率。分别报告分母、样本数和不确定性，不只报一个总准确率。

确定性计分与权限约束的验收目标是：固定测试集计分结果全对、未经确认写入为零、缺题不伪造总分、不得越权。安全信号识别没有可先行承诺的 100% 灵敏度；上线门槛由专业团队根据场景、可承受误差和备援能力批准。模型、题目、阈值或流程变更后重新验证并留版本。

### 建设次序

第一阶段演示早晚关怀、语音未响应的点选回退、量表确认、模拟评分与接收状态，所有语音或模型模拟均明确标识。第二阶段接入真实转写与受控抽取，先在受控测试中比较人工参照。第三阶段在机构、专业人员、隐私制度、排班与备援齐备后开展有限试点。真实临床处置始终由有资质人员负责，不因技术逐步上线而交给模型独立决定。

## 10 评审事项与依据

### 进入开发和试点前分别确认

产品评审先确认早晚时段设置、语音默认关闭、5 至 8 秒点选回退、每日打扰上限、日记与量表分离、三端权限和失败文案。临床评审确认量表中文版本及年龄、施测方式、评分与响应规则、个体化计划和哪些岗位可作安全评估。运营评审确认值守时段、容量、超时备援、外部接收与回访。合规评审确认未成年人、音频和云端模型的数据处理及留存规则。

新增需求可并入 V0.1 的用户端、AI 工作流、数据、验收及待确认章节。除明确补充的规则外，原有志愿者休息、交接、接待上限和普通管理者权限限制不变。本稿不把任何指南当作对同频产品效果或安全性的认证。
